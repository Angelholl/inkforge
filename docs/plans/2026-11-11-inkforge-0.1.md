# 墨炉（Inkforge）0.1 实现计划

**目标：** 2026-11-12 交付 0.1 正式试用版：mock 单章纵向闭环 → Strata 真模型 3 章 + kill -9 崩溃压测 → 20 章过夜挂机 → 角色路由与 Tauri 桌面 GUI 完整化。

**架构：** headless 本地服务（Node 22 + TS + Fastify，REST+SSE，内部 spawn 独立 worker，concurrency=1，租约心跳）+ Tauri 桌面壳（React 19 + Vite 前端，Fastify 服务由壳随壳管理）+ 单文件 SQLite(WAL) 唯一真相源（better-sqlite3，正文 TEXT + append-only chapter_versions + FTS5 trigram）+ 统一 Anthropic Messages client（DEC-2026-1111-03 修正）+ 能力描述符/角色路由 + 上下文预算装配器（绝不整本送）+ 质检 L0→L1→门控→≤2 轮定点重写→needs_human。

**规格（真值源，冲突以decision-log为准）：**
- `docs/decision-log.md` L3-L40：DEC-2026-1111-01（立项选型）/ DEC-2026-1111-02（0.1 范围=Tauri+四段全量）/ DEC-2026-1111-03（Anthropic Messages 协议 + Strata 端点参数 + 风格档案改期）。
- 卡面：`docs/design/card-plan-0.1.md`（本计划的派卡依据）。
- 意向书要点见附录 A（`docs/intent/novel-pipeline.md` 已在库，供交叉阅读）。

**与旧计划的关系：** `docs/design/implementation-plan-v1.md` 系 DEC-2026-1111-02/03 之前的草案（OpenAI 兼容 client、端口 18500、浏览器 GUI、Electron 后期可选），**其调度地位由本计划取代**；执行者不得照抄 v1 中与上述三条决策冲突的条目（client 协议、env 名、GUI 形态、端口）。本计划未涉及的细节若 v1 与 decision-log 不冲突，可作参考但以本计划为准。

### 任务 T01：配置层（STRATA_* 必填校验 + mock 开关）

**文件：** Create `apps/server/src/config.ts`、`apps/server/test/config.test.ts`、`.env.example`。

**接口：** Consumes——`StepName`（shared）。Produces——`loadConfig(env: NodeJS.ProcessEnv): AppConfig`：
```ts
type RoleName = 'planner'|'drafter'|'qc'|'rewriter'|'summarizer';
type ProviderConfig = {name: 'local'|'cloud'; baseURL: string; apiKey: string; model: string;
                       contextWindow: number; maxOutput: number; supportsJsonSchema: boolean};
type AppConfig = {port: number; dataDir: string; mock: boolean;
  providers: {local: ProviderConfig; cloud?: ProviderConfig};
  roles: Record<RoleName, {provider: 'local'|'cloud'; model: string}>;
  budgets: {draft; draft8k; qc; qc8k; rewrite};
  quality: {targetChars: number; scoreThreshold: number; minGain: number; maxRounds: number};
  timeouts: Record<Exclude<StepName,'finalize'>, number>};
function pickBudgetProfile(contextWindow: number): 'draft'|'draft8k';  // ≤8192 → 'draft8k'
```
env 映射见全局约束表；`STRATA_*` 三者任一缺失 → 抛 `ZodError`。

**步骤：**

## 附录 A：规格基线摘要（意向书 + 拍板架构，含 DEC-02/03 修正）

**意向书要点（owner 确认）**：个人使用的全自动长篇小说生成流水线（非写作编辑器），本地为主可切云端，GUI 操作。入口 A 续写（喂小说→蓝图勾画→续写，不注入风格档案，用 voice-match 质检）；入口 B 生成（世界观/角色卡/规则→蓝图→全新生成）。核心管线：蓝图→章节队列→逐章生成→L0→L1→≤2 轮重写→挂机连产 20+ 章。连续性：自动摘要/伏笔/角色状态。人工介入：跑完抽查、点章重写。明确不做：写作编辑器、审稿流转、多人协作。**0.1 范围=MVP 四段全量；入口 A 续写模式整体顺延 0.2**（DEC-01 MVP 切法四段不含入口 A；schema 已预留 `is_original`/kind `'original'`）。

**拍板架构（8 项，经 DEC-02/03 修正后表述）**：① headless 本地服务（Node 22+TS+Fastify，REST+SSE）+ **Tauri 桌面壳**（React 19+Vite；回退=浏览器 `--app`，Electron 0.2 再评估）；② 单文件 SQLite(WAL) 唯一真相源，正文 TEXT+append-only chapter_versions+结构化连续性表，FTS5 trigram；③ DB 持久化 run/step 状态机+独立 worker(concurrency=1)+租约心跳，崩溃断点续跑，残稿 salvage，启动器阻止睡眠；④ **统一 Anthropic Messages client**（DEC-03 修正，Strata 直连 `http://127.0.0.1:47831/v1`，模型 `iq3_xxs`）+能力描述符+角色路由+上下文预算装配器（绝不整本送；稳定前缀在前；iq3_xxs 用分隔符纯文本+客户端解析）；⑤ L0→L1 引用证据 rubric→门控→≤2 轮定点重写；终止=全过且分达标/轮数 2/提升 <5%，停则 needs_human 保留最佳版本；⑥ 风格离线蒸馏不可变档案→每章轮换 3 段；**档案卡改期待 owner 换样例（DEC-03），0.1 不依赖**；⑦ run 前 VACUUM INTO 快照、导出 md、永不就地覆盖、单实例锁；⑧ clean-room，存证 `docs/third-party-references.md`。
