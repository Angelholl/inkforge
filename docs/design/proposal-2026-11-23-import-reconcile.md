## 0. 需求（owner 2026-11-23 两轮原话意译）

1. 项目内做一个「清洗」功能：当发现 MD/TXT 世界观大纲文档与蒸馏档案存在**重合或冲突**时，可选择**保留一方或融合**。
2. 或者：导入新设定集时先勾选蒸馏档案，正式生成之前选择融合/保留一方/其他。

- plot/spectrum/imitation 有独立绑定端点（`routes.ts:1082-1160`），注入面=**仅 planner 参考槽**（drafter 红线不注入，`routes.ts:414/420/426`）。
- style 档案→drafter styleRules/styleDims/fewShot + task 铁则；主/辅/权重/七维来源控件已在书籍设置绑定面板。

## 2. 关键事实：重合分两类（v1 立论保留，B 类形态按评议重构）

**A 类：MD 正文 ↔ 本次导入生成的结构化记录**（确定性，零 LLM）
- §4 人物圣经 ↔ 42 张人物卡（characters 槽）；§7 关系矩阵 ↔ outline 列；§11 悬置线 ↔ foreshadowings 表；§10 文风 ↔ 文风节派生的 style 档案。
- 现状：drafter 每章同时吃「MD 全文（含这四节的散文）」+「其结构化产物」= 双注入。这是今晚 v6 瘦身诉求的真正答案，剥除判定可完全确定性做。

**B 类：MD 正文 ↔ 蒸馏档案**（评议裁定：MVP 内只做确定性警示，不做 LLM 四选一）
- 档案输入是 owner 粘贴的参考作正文（阿美/仙家/舍友/斗罗），不是本书章节；plot/spectrum/imitation 仅进 planner 参考槽，与 MD **无同槽双注入**——「保留一方」对它们是假选项面（调研报告表二）。
- 唯一同槽面=style：参考作档案的规则/样本与 MD §10/§3 并存于 styleRules/fewShot。MVP 处理=**确定性同槽警示**（列出「本书主/辅档案规则 × MD 文风/规则节」并存清单，引导用既有主/辅/权重/七维来源控件处置），不新增裁决机制。
- 「旧宇宙 vs 新宇宙」语义冲突（如光谱档案匿名原型与本书同名人物设定矛盾）：LLM 对照 pass 列 **P2**，owner 坚持进 MVP 须带真实例证（评议要求）。

## 3. 方案骨架（v2）

### 3.1 引擎（纯函数，零 LLM）

输入：书当前 description（或导入草稿 description）+ 骨架节区段 + 绑定档案现状（style 主/辅）。
- **A 类重合清单（确定性）**：按「节→结构化承载」映射表逐项：`承载存在?` → 预置建议（剥 / 保持双注入）；§5 三卷大纲因弧表是 24 章+卷二/三规划原料（outline 列只装卷级聚合+矩阵精炼），预置**保持双注入**。
- **B 类同槽警示（确定性）**：bound style 档案非空 且 description 含文风/规则节 → 提示并存双源，指向绑定面板；plot/spectrum/imitation 绑定仅说明行「planner 参考，不占世界观」。
- 输出=「剥除预览 diff + 警示清单」；引擎不落库、无 LLM。

### 3.2 裁决→机制映射

| 选项 | 动作 |
|---|---|
| 保留 MD 正文 | description 不动 |
| 保留结构化承载（剥正文） | 从 description 剥该节文本（节定位基于精炼文残留的标题行），记录/绑定零触碰 |
| 保持双注入（现状，原「融合/并存」改名） | 两路各喂各槽；= 现状显式化，作默认项与回归钉 |
| 手改合并（冲突/重叠项） | 用户在世界观编辑框直接改文本（已有 UI）；LLM 改写正典不做 |

### 3.3 入口（评议推翻 v1 推荐，采「②先行」）

1. **书籍设置「清洗」按钮（MVP）**：对已入库书跑引擎→预览 diff→确认 PUT meta。今晚这本即时受益；向导 UI 零扩张；apply 恒建新书（`routes.ts:248-250`）故导入侧改造不救存量书。
2. **导入向导内嵌（P1 追加）**：preview 后 apply 前跑同一引擎，裁决并入草稿确认屏。
3. B 类 LLM 对照 + 向导勾档案预选（`routes.ts:1082-1160` 现绑定语义在详情页，预选=新增步骤，膨胀点）→ P2。

### 3.4 边界与非目标

- 不动生成管线槽装配；不动蒸馏作业输入模型；不做「章节自动反哺档案」（continuity 除外，已自动）；不触碰 mandate/落地格/章骨架；不做 LLM 改写正典；8k 档截断行为不变。

## 4. 范围决策（v1 四待定项的评议裁定 → 呈 owner 终拍）

1. 入口：②先行（评议推翻，采纳）；①为 P1。
2. 裁决默认：逐项预置可改（采纳），且「剥」仅对有结构化承载的节预置（评议补）。
3. 融合语义：A 类取消「融合」标签、改「保持双注入（现状）」（采纳）；LLM 改写整体出 MVP。
4. 档案范围：MVP 仅 style 同槽警示（采纳）；plot/spectrum/imitation 裁决出 MVP，owner 坚持则须例证。

## 5. 风险判定（v1 清单 × 评议结论）

- R1 映射表失真：真、可控——命中逻辑是单 token `includes`（`settings-import.ts:494-542`），节题一改检测与抽取同瞎；映射进 shared 常量 + 夹具钉。
- R2 LLM 延迟/稳定性：MVP 无 LLM，消失；P2 复活。
- R3 「保留一方」假选项：真，且是选项集问题非措辞问题——B 出 MVP + 改名后减半；P2 做 B 时必须按槽性写选项。
- R4 预算警示联动：被夸大——剥只降字数，预警单向消失。
- R5 未勾档案不参与：入口②按书内**已绑定**档案全量对照，规避。
- R6 与 mandate 体系相邻易误解：真——验收加「清洗后 mandate/mustHaveBeats/骨架不变」回归钉。
- R7 存量书分叉：真——即②先行的论据。
- **N1（新）**：剥节只准作用于 description 文本，不得回流解析输入（否则丢卡）——验收钉「剥 §4 后 characters=42 不变」。
- **N2（新）**：向导「勾档案」=新增预选步骤，今日绑定在详情页——出 MVP。
- **N3（新）**：覆写回滚依赖引擎确定性——验收钉「同输入重跑逐字节一致」；灾备=imports 归档 re-refine。
- **N4（新）**：planner【书籍简介】~90 字取头窗（`config.ts:141`）——§1–§3 恒在头部、剥除只动 §4 之后，验收加 head 窗 diff 不变钉；outline-suggest 另有 characters/outline 槽补位，worldview 变短是收益非风险。
