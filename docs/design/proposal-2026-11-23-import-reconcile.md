## 2. 泛型原则：重合判定「载体驱动」，不硬编码任何节表

调研报告钉死的解析器行为给出本案的泛型地基——**解析器只认结构骨架（标题/表格/编号），内容无关**（plan 全局约束），且精炼全文**保留标题行**（剥 `#` 留题面，`settings-import.ts:121`）。于是：

**A 类重合（MD 正文 ↔ 本次导入抽出的结构化记录）的判定准则 = 「被抽取消费过的节」**：
- 解析器消费哪节是解析过程自身的既成事实（`includes('人物'/'大纲'/'矩阵'/'文风')` 命中节 + 悬置 H3 块，`settings-import.ts:494-542,447`）——引擎据此声明候选，与具体是哪本书、什么题材、几节骨架**完全无关**。
- 实现：preview DTO 增 `consumedSections: string[]`（服务端廉价改动）；书设置入口对已入库书=对 imports 归档原文重跑纯解析器即得同一清单（引擎确定性，N3 钉）。
- 剥除=在精炼 description 文本里按题面定位该节区段删除；**只作用于 description，绝不回流解析输入**（N1：剥后卡数不变）。
- 未被抽取的节（只活在 description）=无承载 → 引擎自动标「不可剥」。§5 类「部分承载」内容（前 23 章有蓝图、弧表是后续规划原料）泛型预置=保持双注入。

**B 类重合（MD 正文 ↔ 蒸馏档案）**（评议裁定：MVP 只做确定性警示）：
- 档案输入是 owner 粘贴的参考作正文，不是本书章节；plot/spectrum/imitation 仅进 planner 参考槽，与 MD **无同槽双注入**——「保留一方」对它们是假选项面（调研报告表二）。
- 唯一同槽面=style：参考作档案的规则/样本与 description 中文风/规则类内容并存于 styleRules/fewShot。MVP=确定性警示（列「本书主/辅档案 × 消费过文风/规则类节」并存清单，处置走既有主/辅/权重/七维控件）。
- 「旧宇宙 vs 新宇宙」语义冲突（参考作同名人物/行为 vs 本文档设定）：LLM 对照 pass 列 **P2**；owner 坚持进 MVP 须带真实例证（评议要求）。

## 3. 方案骨架

### 3.1 引擎（纯函数，零 LLM，格式无关）

输入：description（当前库内值或导入草稿）+ 消费节清单（来自解析器/归档重解析）+ 绑定档案现状（style 主/辅）。
- 输出：「剥除预览 diff + 警示清单」；不落库、无 LLM、无书特异性知识。
- 作用层=库内 description 文本：对来源是 MD 设定集、纯文本世界观稿还是手填简介**一视同仁**；非骨架 txt 的「文档导入」本身是另一个入口扩展（P2 候选，见 §3.4）。

### 3.2 裁决→机制映射

| 选项 | 动作 |
|---|---|
| 保留 MD 正文 | description 不动 |
| 保留结构化承载（剥正文） | 按题面从 description 剥该节文本，记录/绑定零触碰 |
| 保持双注入（现状，原「融合/并存」改名） | 两路各喂各槽；默认项+回归钉 |
| 手改合并 | 用户在世界观编辑框直接改文本（已有 UI）；LLM 改写正典不做 |

### 3.3 入口（两入口共享同一引擎，泛型 owner 指认后的定位）

1. **书籍设置「清洗」按钮（MVP）**：对任意已入库书跑引擎→预览 diff→确认 PUT meta。不依赖导入流程，今晚这本只是首个试例。
2. **导入向导内嵌（P1）**：preview 后 apply 前跑同一引擎，裁决并入草稿确认屏——面向「以后每次导入任意大纲文档」的主流程，功能长期正身在①。
3. B 类 LLM 对照 + 向导勾档案预选（现绑定语义在详情页 `routes.ts:1082-1160`，预选=新增步骤，膨胀点）→ P2。

### 3.4 边界与非目标

- 不动生成管线槽装配；不动蒸馏作业输入模型；不做「章节自动反哺档案」（continuity 除外，已自动）；不触碰 mandate/落地格/章骨架；不做 LLM 改写正典；8k 档截断行为不变。
- MVP 不新增文档格式解析（纯 txt 世界观稿/大纲稿的独立导入器另案）。

## 4. 范围决策（评议裁定 → 呈 owner 终拍）

1. 入口：②先行、①为 P1（采纳评议）；泛型化后 ① 是长期主入口而非可选项，先后只是排期序。
2. 裁决默认：逐项预置可改，「剥」仅预置给被消费且已全量承载的节（采纳+泛型化）。
3. 融合语义：A 类取消「融合」标签、改「保持双注入（现状）」（采纳）；LLM 改写整体出 MVP。
4. 档案范围：MVP 仅 style 同槽警示（采纳）；plot/spectrum/imitation 裁决出 MVP，owner 坚持则须例证。

## 5. 风险判定（v1 清单 × 评议 × v2.1 泛型修订）

- R1 映射失真：**泛型化后大幅消解**——不再有硬编码节表，判定=「解析器消费过⇒有承载」，与解析器同生共死（词表漂移风险是解析器既有风险，夹具已钉）。
- R2 LLM 延迟/稳定性：MVP 无 LLM，消失；P2 复活。
- R3 假选项：真（选项集问题）——B 出 MVP + 改名后减半；P2 做 B 时必须按槽性写选项。
- R4 预算警示联动：被夸大——剥只降字数，预警单向消失。
- R5 未参与对照的档案：入口②按书内已绑定档案全量对照，规避。
- R6 与 mandate 体系相邻易误解：真——验收加「清洗后 mandate/mustHaveBeats/骨架不变」回归钉。
- R7 存量书分叉：真——②先行论据（泛型后仍成立：任意存量书可洗）。
- N1 剥节不得回流解析输入：真——验收钉「剥后卡数/树/伏笔/绑定不变」。
- N2 向导预选=膨胀点：采纳出 MVP。
- N3 引擎确定性（书设置入口靠归档重解析）：真——验收钉「同输入重跑逐字节一致」；灾备=imports 归档 re-refine。
- N4 planner【书籍简介】~90 字取头窗（`config.ts:141`）：泛型表述=「剥除不得动 description 头部区段（首 blockquote 定位句起）；若首节即被消费（如某些骨架以人物开篇），预览须显式示警头窗变化」——验收加 head 窗 diff 钉。

## 6. 验收口径

- 引擎纯函数单测：中性仿形夹具（《示例之作》系，沿解析器测试内容无关律）+ v6 归档副本作真实例两型；逐节判定（消费且全量承载→预置剥；部分承载/未承载→预置保持/不可剥）；style 警示触发/不触发两面。
- HTTP：清洗 confirm → 回读 description 剥节正确；characters/outline 列/伏笔/骨架/mandate/style 绑定全部不变（N1/R6 钉）；全「保持双注入」=逐字节现状（回归钉）；引擎重跑一致（N3）。
- 注入重放：剥节后 drafter worldview 变短、其余槽逐字节不变；planner task 头窗不变（N4）。
- GUI 未验证（owner 真实测试）点位：书设置清洗按钮、预览 diff、确认流。
