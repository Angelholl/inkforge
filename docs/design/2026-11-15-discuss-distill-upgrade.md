## 一、现状诊断（apps/server/src/style/）

当前蒸馏 = **单次 LLM 调用**（distill.ts）：
1. **采样策略整体缺席——"太简单"的技术根因**：用户粘贴全文 → 所有文本一次性 join 塞进单条 user 消息，无分段采样、无均匀覆盖（开头/中段/结尾）、无输入预算控制；长文本直接顶爆上下文或被截断，蒸馏质量随文本长度随机波动；
2. 提示词 `RULES_INSTRUCTION` 硬编码在源码，产出 5-10 条 `RULES:` 行——**无结构化维度**（对照立项要求的：视角/时态、句长分布分位、对话占比、比喻与感官密度、常用词/禁用词、段落节奏、章节开头结尾习惯、情绪基调）；
3. 档案 = rulesText + 全量 samples + metrics_json；同 source_hash 版本+1 旧行不改（不可变档案，✓ 保留）；
4. 注入端：renderStyleBlock（规则 + 每章轮换 3 段，1200 字预算截断）+ pickStyleSamples（已有，✓）；
5. **缺口（0.2 草案 F2 已登记，至今未补）**：voiceRefMetrics 从不传入生成管线（l0.ts 启用条件、chapter.ts 调用不带）——立项设计的 voice-match QC 整条链缺席；
6. UI：名称 + 文本 → 蒸馏裸表单（StyleProfilesSection），无版本视图、无参数、无产物预览、无人工确认环节。

对照立项意图「离线蒸馏不可变档案（量化规则 + 8-12 段样本），每章轮换 3 段；续写模式不注入，用 voice-match QC」：**样本与轮换已达标，采样与规则深度不足，voice-match QC 整体缺席**。

## 二、SubTrans 可借鉴的设置模式（按价值排序）

| # | SubTrans 模式 | 对应资产 | 平移到蒸馏的价值 |

## 二.5、立项 GitHub 项目补充参考（2026-11-15 公开 README 实读）

### MirrorNovel——立项评审认定的「最直接证据」，蒸馏设计的对标系

1. **采样规格**：长文蒸馏「最多均匀分析 20 段、每段约 2 万字符，**覆盖开头、中段与结尾**」后合并报告——正是当前实现缺的采样层；参考库总预算 500 万字符、文本上限 10MB。
2. **结构化档案维度**：节奏、对话、描写、情感基调、写作特点、特色词汇、章节结构七维；另有独立**结构分析**（阶段节奏、冲突与伏笔等抽象方法）——结构与文风分离出档。
3. **风格六轴**：叙述温度/语言密度/叙述者姿态/节奏/幽默/情绪表达，随题材/标签自动定调，也可手调——比 5-10 条自由文本规则可量化得多。
4. **persona 与快照**：作者声线/语气/节奏/词汇偏好/写作规则；**作品保存 persona 快照，后续改模板不影响已有作品**——与 inkforge「不可变档案 + adopted_at 记录」理念同构，直接可采。
5. **产物人工确认环节**：分析结果**可编辑、需确认应用后才生效**——蒸馏不是黑盒一键，而是「蒸馏 → 预览编辑 → 确认入库」三步；inkforge 可在不可变档案前加确认门，编辑发生在入库前。
6. **注入策略细节**：每次创作最多选 3 个已蒸馏参考；文风示例默认关闭，每参考 1 段 × 240 字符、合计 3 段原文片段——与立项轮换公式（(N-1) mod count）+ 3×240 字预算高度一致（立项即源于此），当前 renderStyleBlock 已实现骨架。
7. **失败教训（立项已定为前置门槛与回归项，须写进验收）**：空样本库时注入无效；长度校验≠语义校验；无抄用审计（立项对策=L0 加「禁止连续 15 字以上重合」检测）；真实 A/B 未通过。
8. **编辑引擎三阶段**（结构重构 → 风格一致 → 去 AI 化，单章与整本）+ 全文调优（长篇重复/节奏/伏笔后台逐章优化）——这是「批量校对」的成熟形态参照。

### Pagekin——「拆解仿写」：蒸馏的进阶形态

1. **拆解仿写**：AI 拆解参考小说的**结构**、提取**文风**、**反推章节蓝图**，生成「仿写约束」供写作时参考；参考内容只进知识库和拆解结果，不混入正文——蒸馏产物从「文风档案」扩展为「文风 + 结构 + 蓝图反推」三层，且明确「参考不混入正文」的红线（对应抄用审计）。
2. **写作 Skill 导入**：自包含提示词型 SKILL.md 绑定到规划/写稿/审稿/修稿阶段（如「去 AI 味」）——可组合的提示词插件机制，与蒸馏讨论稿的「可编辑模板」是同一方向的多预设版。

### 对批次方案的修订

MirrorNovel/Pagekin 的输入把优先级改排了——**采样层从「顺带」升为第一批核心**（没有它，其余都是空中楼阁）：

- **批次一（采样 + 结构化档案 + 确认门）**：均匀采样器（≤20 段覆盖首/中/尾，本地预算控制）；档案结构化（七维字段 + 风格六轴量化值，替代纯 RULES 行文本）；蒸馏 → 预览编辑 → 确认入库三步流；RULES 行协议保留为六轴的文本补充。
- **批次二（模板/参数 + 自评接线补 F2）**：提示词模板落库可编辑 + 恢复默认；高级参数折叠区（温度/长度走 summarizer 角色）；蒸馏后 held-out 自评打分写 metrics_json；生成管线接入 voiceRefMetrics；**L0 抄用检测（连续 15 字重合）**——MirrorNovel 失败教训的立项对策。
- **批次三（persona 快照 + 版本视图）**：书绑定档案时保存快照（后续改档案不影响已绑定书）；档案列表版本展开 diff。
- **批次四（术语表 + 批量校对）**：术语槽（人名/地名/专有词）；三阶段式批量校对（结构→风格→去 AI 味，复用 rewrite 管线）。
- **候选（另行立项）**：Pagekin 式拆解仿写（结构拆解 + 蓝图反推）——价值高但动蓝图协议，建议 0.3 议。
