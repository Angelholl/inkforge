## 一、全流程逐阶段对照

| 阶段 | inkforge 现状 | Pagekin（人机协作路线） | MirrorNovel（全自动路线） | 差距定性 |
|---|---|---|---|---|
| 建书/导入 | 入口 A 导入章（含可选摘要）；入口 B 建书 | 书房管理；.txt/.md/.epub 导入；「参考小说」拆解仿写 /「我的原稿」续写 | .txt 上传或粘贴导入续写（方向+字数） | **格式面**：缺 .md/.epub 解析 |
| 设定 | 入口 B：世界观/人物卡/剧情大纲 | 架构四节：前提/角色/世界观/大纲，逐节确认 | 定调：题材/分类/标签（男频女频）+主角+世界观 | **缺题材/标签维度**——它驱动六轴自动定调 |
| 蓝图 | 单层章节蓝图（GOAL/BEATS/HOOK）+ books.outline 一段文字；outline-suggest 一次产 N 章 | 每章蓝图：主角小目标/冲突转折/悬念钩子/出场人物；**分批生成、中断可续** | **三级蓝图**：全书篇章→篇章内小阶段→未来 10-20 章滚动执行卡；蓝图复核与提案应用 | **结构性差距**：单层 vs 三级滚动 |
| 正文生成 | 单章 generate + generate-all 挂机（20 章）+ 断点续跑 + 残稿 salvage | 单章或批量 ≤10 章；运行侧页（进行中/历史/诊断） | 整本/单章/导入续写；暂停；断线后台继续 | 运行时骨架 inkforge **更强**（run 状态机+租约+kill -9 验证）；缺批量窗口控制 |
| 质检修稿 | L0 确定性 → L1 引用 rubric → 门控 → ≤2 轮定点重写 → needs_human（全自动） | 审稿报告 → **人工逐条勾选/忽略+自加意见** → 修稿 → **差异对比逐段确认** → 定稿 | 专家团审稿 → 修订；编辑引擎三阶段（结构重构→风格一致→去 AI 化）；全文调优 | **路线分歧点**：inkforge 全自动 vs Pagekin 人审 vs MirrorNovel 半自动 |
| 段落级操作 | SelectionRewrite 仅重写 | 选中续写/润色/扩写/改成对话 | 编辑引擎覆盖 | 功能面窄 |
| 连续性 | character_states + foreshadowings 表 + 摘要链；**伏笔无手动 CRUD** | 剧情按章节追踪：主线/支线/伏笔埋设推进解决；角色关系图谱 | 摘要+角色状态+伏笔+未决问题+阶段目标+情绪变化；**计划偏离复核**（近期正文 vs 安排语义检查） | 表结构已在，**缺 UI 与偏离复核** |
| 版本 | append-only chapter_versions + rollback（回退为当前） | 历次稿件保留，回退成**新草稿** | 历史版本恢复时**重建摘要与续写上下文** | inkforge rollback 直接切 current——**回退为草稿**（Pagekin 语义）更安全 |
| 导出/备份 | export md | 合并 md / 分章 md / TXT；WebDAV 备份 | 导出 | 格式少 |

**结论一句话**：inkforge 的运行时骨架（状态机/恢复/挂机）强于两家参照；差距集中在**蓝图层级（单层 vs 三级滚动）、人机协作层（全自动 vs 可介入）、设定维度（无题材标签）、连续性 UI（表在而无界面）**四块。

## 二、可平移项清单（按投入产出排序）

1. **三级蓝图/滚动执行卡**（MirrorNovel）：books 增蓝图层级（卷→阶段→滚动卡），outline-suggest 升级为分次产卡；规划偏离复核（近期正文 vs 卡安排语义检查，进 L1 或独立步）。**动 planner 协议，最大件。**
2. **审稿报告人工勾选 + 修稿差异确认**（Pagekin）：L1 findings 已结构化（引用+severity），缺的是 GUI 勾选面 +「按勾选项定点重写」（rewrite 输入=勾选问题清单，管线已在）。人机协作最小切入。
3. **段落级操作扩展**（Pagekin）：SelectionRewrite 增续写/润色/扩写/改对话四种指令预设——管线完全复用，仅提示词预设 + UI 按钮，最小件。
4. **题材/标签维度**（MirrorNovel）：books 增 genre/tags 列（migration 0005），入口 B 表单补字段；为六轴自动定调与 QC 维度打底。
5. **伏笔/主线手动 CRUD**（Pagekin；DEC-2026-1114-03 已列为候选）：foreshadowings 表现成，补 API+详情页 UI。
6. **回退语义改「回退为新草稿」**（Pagekin）：rollback 产 kind='manual_edit' 新版本而非切 current，append-only 语义更纯。
7. **导入格式**：.md/.epub 解析（Pagekin）；.md 小、.epub 需解析库（依赖引入需议）。
8. **导出格式**：分章 md/TXT（现仅合并 md）。
9. **运行侧页「历史/诊断」**（Pagekin）：runs 列表已有，诊断页（心跳/租约/worker 状态）为运维向，低优先。

**不建议平移**：MongoDB/服务端形态（立项已否）；知识库/向量检索（单机场景过度设计，FTS5 已够用）；Skill 提示词包机制（与蒸馏批次二的模板落库合并考虑即可，不单独立项）。

## 三、建议分期

- **流程批次一（小件快跑）**：段落级四操作（第 3 项）+ 伏笔 CRUD（第 5 项）+ 导出格式（第 8 项）——全部复用既有管线，低风险；
- **流程批次二（人机协作）**：审稿勾选 + 勾选项定点重写（第 2 项）+ 回退语义修正（第 6 项）；
- **流程批次三（蓝图升级）**：题材标签列（第 4 项）+ 三级蓝图/滚动卡 + 偏离复核（第 1 项）——动协议，先出实现计划评议再动工；
- **流程批次四（输入输出）**：.md 导入（第 7 项小半）+ .epub（依赖评估后定）。
